# TypeStat

统计你每天敲了多少字——**包括打出来又删掉的**。

Windows 桌面程序。全局键盘钩子数按键，编辑器插件报上精确字数。数据只存在本机。

[English](README.en.md)

---

## 它回答什么问题

大多数「打字统计」只数最终留在文档里的字。但真实的工作量里有一大块是反复修改：
敲下去、看一眼、退回去重敲。那部分在别的工具里是看不见的。

TypeStat 两头都记：

- **插入**记一笔，**删除**也记一笔，`净字数 = 插入 − 删除`；
- 退格率、坐下时长、真正在敲的分钟数、每小时分布、每个应用各敲了多少，都从同一批记录里算；
- 每一页上的数字都由后端算出来，界面只负责画。

## 两个口径，别把它们混起来

这是这个程序最需要先说清楚的一件事。

|  | 按键数 | 字数 |
|---|---|---|
| 怎么来的 | 全局低级键盘钩子（`WH_KEYBOARD_LL`） | 编辑器插件主动上报 |
| 覆盖范围 | 所有应用，装完就有 | 只有装了适配器的应用 |
| 含义 | 按了多少次键 | 往文档里放进了几个字符（删掉的另记） |

**两者不可换算。** 用拼音打「你好」，逐个敲是 5 次按键 + 1 次选词上屏，
一句话上屏可能只有 1 次按键。钩子无从分辨这些，只有编辑器自己知道文档里
多了几个字符。所以字数那一栏在没适配器的应用上显示的是
**「量不到」，不是 0**——这两个值在这个程序里从来不共用一根轴。

## 隐私

- **不记录任何输入内容。** 数据库里只有「哪个物理按键、哪一天、按了多少次」
  （`vk_code` / `scan_code` / 计数），没有顺序、没有文本、没有窗口标题。
- **适配器只上报两个整数。** 载荷是 `{app, input, delete}`——应用名加两个数字。
  WPS 那边读的是文档的字符计数（`doc.Characters.Count` 的变化量），兜底路径上
  会取一次 `Range.Text` 的**长度**——取完立即丢弃，不存、不传、不落盘。
- **数据只在本机**：`%APPDATA%\com.typestat.app\typestat.db`。
- **唯一的出站流量**是「总结」页生成正文时，把**数字和应用名**发给一个
  OpenAI 兼容接口（默认 DeepSeek）。这一页不配也能用——会退回本地模板。
  接哪家、什么时候发，都由你决定。
- 接口密钥用 Windows DPAPI 加密后存在同一个库里，换个 Windows 账户或把库拷到
  别的机器都解不开。

## 十一页

| 页 | 看什么 |
|---|---|
| 今天 | 今天的总账：敲入、退格、净字数、坐下时长、速度 |
| 时段 | 24 小时逐时的按键分布 |
| 时长 | 按天看坐下时长与真正在敲的分钟数 |
| 趋势 | 近 7 / 30 / 90 天的按键与字数走势 |
| 热力 | 按天 × 小时的密度图 |
| 键位 | 键盘热力图，看哪些键按得最多，区间可选今天 / 7 / 30 / 90 天 |
| 应用 | 每个应用各敲了多少，字数覆盖率一目了然 |
| 明细 | 分应用对账：按键和字数并排，两列的地盘不一样，横着比没有意义 |
| 总结 | 把一期（周 / 月）的数据读成一段话，可存档回看 |
| 适配器 | 插件上报通道的状态：端口、令牌、最近有没有收到数据 |
| 设置 | 采集状态、手动重建钩子、已知限制、数据库位置 |

## 装

从 [Releases](../../releases) 下载安装包（`.msi` 或 `.exe`）。

需要 Windows 10/11 与 WebView2 运行时（Windows 11 自带）。

## 从源码构建

需要 Node 18+、Rust 稳定版（MSVC 工具链）。

```bash
npm install
npm run tauri dev      # 开发模式
npm run tauri build    # 出安装包
```

打包器（WiX、NSIS）由 Tauri CLI 在首次构建时联网下载，网络不通会失败。
这时候可以只出可执行文件，跳过打包：

```bash
npm run tauri build -- --no-bundle
```

跑测试：

```bash
cd src-tauri && cargo test    # Rust
cd .. && npm run build        # 前端（内含 tsc --noEmit）
```

## 适配器（可选）

精确字数只能由应用自己报。目前有两个适配器，不装也能用，只是字数量不到。

### WPS 文字

在 TypeStat 的「**适配器**」页点一下「装进 WPS」就行。程序把加载项文件装在它自己
身上（不用装 Node、不用找目录），端口和令牌它本来就知道，会一起填好。
**装完必须完全退出 WPS 再打开**——加载项只在 WPS 启动时加载一次。

想手动装、或者装到另一台机器上，同一页的「存出插件文件」会把两份插件的文件存到
一个文件夹里，说明见 [`wps-addon/README.md`](wps-addon/README.md)。

### Obsidian

把 `obsidian-plugin/` 里的 `main.js` 和 `manifest.json` 复制到

```
<你的库>/.obsidian/plugins/typestat/
```

然后在 Obsidian 的「第三方插件」里启用，并在插件设置里填上端口和令牌——
这两个值在 TypeStat 的「适配器」页看得到。

### 接收端

两个适配器都往 `http://127.0.0.1:<port>/report` POST 一个
`{app, input, delete}`，带上 `X-TypeStat-Token` 头。端口在 42180–42189 里挑第一个
空闲的（每次启动都重挑，但只有它自己在用这一段，所以实际上不会变）；
**令牌在首次运行时生成并永久保存，之后固定不变**——要换就点「适配器」页的
「换一个」，换了之后装在插件里的那一份要跟着改。
（这一条是有意为之：要是每次启动都换，你每次开机都得重新抄一遍令牌。）

接收端只绑回环地址，**每个请求都验令牌**，这是唯一的防线——CORS 是 `*`，
因为加载项页面跑在 `file://` 源上，卡住 Origin 挡不住真正的攻击者
（非浏览器客户端本来就能随便写 Origin），只会把插件挡在外面。
**没有任何一个端点是不带令牌就能拿到 200 的**，这是刻意的：否则任何网页都能
`fetch` 一下确认「这台机器上装着 TypeStat」。

## 已知限制

不是 bug，是 Windows 的规矩，写出来免得你以为漏记了。

- **管理员窗口里的输入收不到。** 程序未提权时 UIPI 会阻止钩子收到发往更高完整性
  级别进程的输入（任务管理器、以管理员身份运行的程序）。以管理员身份运行 TypeStat
  才能覆盖它们。
- **部分游戏和安全软件会屏蔽钩子。** 反作弊、DRM 播放器、网银控件会主动拦截全局
  键盘钩子，绕不过去。
- **钩子会被系统悄悄摘掉。** 回调超时累计 10 次后 Windows 会把钩子从链上移除，
  而且没有任何通知 API。程序内置看门狗每 60 秒交叉校验一次并自动重建；
  设置页也留了手动重建按钮给它兜底。
- **「量不到」不是 0。** 没装适配器的应用没有字数，界面上写的是「量不到」。

## 仓库结构

```
src/                    React 前端（无路由库，自己分派）
  pages/                十一页
  components/           LinePlot、KeyboardHeatmap、DayBar
  dev/mockBackend.ts    浏览器里用的假后端，配合 app-preview.html 预览界面
src-tauri/              Rust 后端
  hook/                 全局钩子（键盘、鼠标、看门狗）
  collector/            事件归类、自动重复过滤、前台应用归属
  db/                   SQLite（WAL），表和迁移
  adapters/ipc.rs       本地接收端（axum）
  report/               「总结」：周期算术、清单渲染、模型调用、DPAPI 密钥
wps-addon/              WPS 文字加载项（JS）
obsidian-plugin/        Obsidian 插件
design-demos/           早期界面方向稿（静态 HTML，与成品无关）
```

数据流是单向的：钩子只做「读字段 → 入队 → 返回」，绝不在回调里查 UIA 或写库
（低级钩子的回调必须在 300ms 内返回，超时会被系统摘钩）；统计和落库都在
采集线程里做，按分钟批量写。
